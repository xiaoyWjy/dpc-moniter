# 浙大宁波理工学院安全保卫部 · 公告监控（云端版）

在 GitHub Actions 上每 30 分钟检查一次安全保卫部网站，发现含有关键词的新公示就推送到钉钉群。
**不需要自己的电脑开机**，也不需要服务器。

---

## 一次性设置（约 5 分钟）

### 1. 在 GitHub 新建一个空仓库

名称随意，比如 `bwc-monitor`。私有仓库也行（每月 2000 分钟免费额度，这套每 30 分钟跑一次约用 700 分钟，够用）。

**不要**勾选自动生成 README，保持空仓库。

### 2. 把本项目推上去

在本目录打开终端，把 `<你的仓库地址>` 换成上一步的地址：

```bash
git remote add origin https://github.com/<你的用户名>/bwc-monitor.git
git branch -M main
git push -u origin main
```

第一次推送会弹浏览器让你登录 GitHub，登录完就好。

### 3. 添加两个 Secret（钉钉的密钥不放代码里）

仓库页面 → **Settings** → 左侧 **Secrets and variables** → **Actions** → **New repository secret**，加两条：

| Name | Secret |
| --- | --- |
| `BWC_DINGTALK_WEBHOOK` | 钉钉机器人的 Webhook 地址（`https://oapi.dingtalk.com/robot/send?access_token=...`） |
| `BWC_DINGTALK_SECRET` | 加签密钥（`SEC...` 开头） |

### 4. 启用 Actions

仓库页面 → **Actions** 标签页 → 如果提示 workflows 未启用，点 **I understand my workflows, go ahead and enable them**。

### 5. 手动跑一次验证

Actions → 左侧「安全保卫部公告监控」→ 右侧 **Run workflow** → 绿色按钮。

跑完点进这次运行，应该能看到：

```
[通知公告] 抓取 40 条，新 0 条
[新闻动态] 抓取 20 条，新 0 条
没有新公告。
monitor exit code: 0
```

绿勾即为成功。之后它会自己每 30 分钟跑一次。

## 它会怎么工作

```
每 30 分钟（GitHub Actions）
   ↓
抓 通知公告（前 2 页 40 条）+ 新闻动态（第 1 页 20 条）
   ↓
和仓库里的 state.json 比对，找出新公告（按 wbnewsid 去重）
   ↓
标题命中 废旧 / 清理 / 电动自行车 / 电动车 / 通行证 / 非机动车
   ↓
钉钉群机器人推送 + 把新状态提交回仓库
```

`state.json` 提交回仓库是去重的关键——下次运行时读它，就知道哪些已经推过了，所以**同一条公告只会推一次**。

仓库里已经带了从本机导出的 `state.json`（当前 60 条已读），所以第一次运行**不会把历史公告刷屏**。

## 关于「及时性」

GitHub 的定时任务有两点要知道：

1. **不是精确准点**。官方说明是高负载时会延迟，实测通常几分钟内，偶尔会晚到十几二十分钟。对学校公示来说够用。
2. **最短间隔 5 分钟**，这里设的是 30 分钟。想更快就改 `.github/workflows/monitor.yml` 里的 `cron: "*/30 * * * *"`，比如改成 `*/15 * * * *`（每 15 分钟）。注意私有仓库的免费额度是按运行时长算的，跑得越勤消耗越多。

> 公开仓库的 Actions 完全免费、不限额。

## 改关键词

改 `config.json` 里的 `keywords`，提交即生效（下一次运行就用新词）：

```json
"keywords": ["废旧", "清理", "电动自行车", "电动车", "通行证", "非机动车"],
```

- 子串匹配、不区分大小写；写 `"re:^关于.*公示"` 就按正则处理
- `match_mode`: `any` 命中任一即推；`all` 必须全命中
- `exclude`: 命中这些词就不推（优先级更高）
- `match_body`: `true` 时连正文一起匹配（会多抓详情页，慢一些）

想增加监控栏目，复制一段 `sites` 改 `wbtreeid` 即可（1179 新闻动态、1184 规章制度、1185 学校文件、1186 其他文件、1176 党建动态、1177 安全知识）。

## 看历史和排障

- **每次运行的日志**：Actions → 点进某次运行 → `check` → `检查新公告`
- **命中记录**：仓库里的 `hits.log`（每条一行，`HIT` 表示推送了，`MISS` 表示没命中关键词）
- **最近一次命中的网页摘要**：`latest.html`

常见失败：

| 现象 | 原因 |
| --- | --- |
| 抓取 0 条 / 连接失败 | 学校网站临时故障，或 GitHub 出口被拦（少见）。失败会自动重试 3 次，偶发不用管 |
| 钉钉返回 `310000` | 加签密钥不对，检查 Secret |
| 钉钉返回 `keyword not in content` | 机器人安全设置用了「自定义关键词」，但消息里没有该词。改成「加签」，或用关键词「安全保卫部」 |
| 定时任务突然不跑了 | 仓库 60 天无提交会被自动停用，`keepalive.yml` 每月发一次空提交避免这点 |

## 本机版还留着吗？

`D:\deepseek\deepseek harness\bwc-monitor\` 是本机版，靠 Windows 任务计划每 2 小时跑一次，需要电脑开着。

**两边同时跑会重复推送同一条公告**（各自维护自己的已读记录）。云端验证通过后，建议把本机任务删掉：

```bat
schtasks /delete /tn "BWC-Monitor" /f
```

如果想留作备份（比如 GitHub 那次被墙了），就保留，忍受偶发重复。
